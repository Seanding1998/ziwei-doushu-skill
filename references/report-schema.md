# 报告数据 Schema（AI 产出 → 脚本渲染）

> **铁律：AI 不写 HTML。** AI 只产出本文件规定的 JSON，HTML 由 `scripts/generate_report.py` 渲染。
> 这样报告版式每次一致、省 token，而且可校验。

---

## 一、总体流程

```
1. python ziwei.py chart --date ... --json                        → chart.json（脚本算的盘面）
2. python prepare_template.py --chart chart.json -o analysis.json → 分析工作单（盘面事实已预填）
3. 【AI 分析】读 chart.json + references/interpretation.md，按序产出：
     ① interpretation_notes —— 九步分析留痕，每步「看到什么 → 判断什么」，每步 ≥40 字
     ② findings —— 主线 + 关键点（≥3 条）+ 矛盾点
     ③ 正文 —— skeleton / star_system / mutagen_axis / palace_reading /
              palace_details（12 宫）/ strengths / weaknesses /
              decadal_trend / current_year / risk_boundary
     ④ patterns —— 逐项裁断（脚本只判条件，satisfied 必须由 AI 填）
4. python generate_report.py --chart chart.json --analysis analysis.json --output report.html
5. python check_report_language.py report.html   → 退出码 0 才算通过
```

> ⚠️ **第 3 步的顺序是强制的。** 脚本会检查 `interpretation_notes` 与 `findings`：
> 缺失、或某一步少于 40 字，**校验直接失败**。这是为了拦住「跳过分析、直接拼正文」的路径。
> **正文写得好不能替代分析留痕**——报告的价值在依据链，不在辞藻。

第 4 步的 `--validate` 会做完整性与语言闸门校验，**不通过会以非 0 退出并阻断交付**。

---

## 二、顶层结构

```json
{
  "meta":     { "name": "当事人称呼（可留空）", "date": "2026-10-15" },
  "chart":    { ... },      // ziwei.py chart 的完整输出，原样塞入
  "analysis": { ... },      // 见下节
  "md_full":  { "定盘": "...", "逐宫": "..." }   // 可选：逐字全文附录
}
```

也可以分开传：`--chart chart.json --analysis analysis.json [--md-full full.json]`。

---

## 三、`analysis` 字段（核心）

> **两部分**：`interpretation_notes` + `findings` 是**分析**（怎么想的）；其余字段是**成文**（怎么说）。
> **先分析、后成文**，脚本按这个顺序校验。

### 3.0 分析留痕（强制，缺则校验失败）

**`interpretation_notes`** —— 九步逐步留痕，每步 ≥40 字，写「看到了什么 + 据此判断什么」：

| 键 | 该写什么 |
|---|---|
| `step1_定盘` | 真太阳时是否近交界、有无往事校验 → 定 A/B/C |
| `step2_骨架` | 命宫／身宫／来因宫／五行局／命主身主 → 这个人的「场」 |
| `step3_星系类型` | 紫微落宫 → 六种组合之一，以及它落在哪个宫位意味着什么 |
| `step4_本宫三方四正` | 四方各宫星曜 + 强弱关系（如命强迁弱） |
| `step5_亮度` | 强星集中在哪、**失辉共几处、逐宫是哪几宫**（漏列一宫即口径不全）→ 由此看出什么结构规律 |
| `step6_辅佐煞杂曜` | **六吉六煞的成对／同宫／对拱一律照 §二 的配对表引用**（不要自己判断）、六煞落哪、禄存被夹在哪 |
| `step7_四化三层` | 生年四化落点 + 自化（离心/向心）→ 主轴；三层不可混 |
| `step8_夹宫` | 命宫两邻吉凶并夹的具体构成 |
| `step9_格局裁断` | 对脚本给的 `patternCandidates` 逐项裁断，说明为何成立/不成立 |

**`findings`** —— 从九步收敛出的关键发现：

```json
{
  "主线": "一句话主轴（≥30 字）",
  "关键点": ["3～7 条，每条一个独立发现"],
  "矛盾点": "盘面内部或外显与内里的矛盾（可留空）"
}
```

> 这两部分会渲染进报告的**第十二节「分析留痕」**（主线+关键点常显、九步过程折叠），
> 全文附录与技术留痕**不再重印同一份内容**（第四轮去重：九步留痕只保留第十二节那一份）。
> **别把 `_CHART_FACTS` 抄一遍**——那是盘面复述，不是分析。

> ⚠️ **三张表由脚本渲染，不要在正文里重写它们**（第四轮两张 + 第五轮一张）：
> §二 的「宫位关系（对宫／三合／两邻）」来自 `chart.palaceRelations`，
> §二 的「六吉六煞分布与配对」来自 `chart.pairingFacts`，
> §九 的「大限十二宫落本命宫位」与「大限四化落点」来自 `chart.decadalPalaceMaps`。
> 正文凡提到「对宫 X」「X 在 Y 三合」「X、Y 分居 Z 两邻」「本限／大限某某宫」，
> **只能照这三张表读**；写错会被 `PALACE_RELATION_MISJUDGED` / `DECADAL_PALACE_MISNAMED` 拦下。
> 凡提到「六吉／六煞／辅弼／昌曲／魁钺／羊陀／火铃／空劫」的**成对、不成对、同宫、对拱**，
> 也**只能照配对表读**——写错会被 `AUSPICIOUS_PAIRING_MISSTATED` 拦下（第五轮 BLOCKER 的原型）。
> 盘面有的生年禄/权/科/忌四类都要在星曜表与宫位图上标全（含辅星），
> 缺任一类会被 `MUTAGEN_MARK_INCOMPLETE` 拦下。

### 3.1 必填 + 字数下限（脚本会卡）

| 字段 | 类型 | 下限 | 说明 |
|---|---|---|---|
| `firming_level` | string | — | **定盘可信度**：`A 可信` / `B 基本可信` / `C 需复核` |
| `firming_reason` | string | — | 定盘依据（真太阳时是否近交界、是否做过往事校验） |
| `skeleton` | string | 100 | 命格骨架：命宫/身宫/来因宫/五行局/命主身主 合成一段「这个人的场」 |
| `star_system` | string | 100 | 星系结构：紫微落宫→星系组合、三方四正、主星庙旺分布特征 |
| `mutagen_axis` | string | 120 | 四化主轴：生年四化落点的意义 + 自化揭示的「明有实无」 |
| `palace_reading` | string | 200 | 逐宫总述（若给了 `palace_details` 则作为导语） |
| `strengths` | array | — | 优势结构，3–5 条，**必须可执行**，不要「努力就会好」这类空话 |
| `weaknesses` | string/array | 80 | 结构性短板，3–5 条 |
| `decadal_trend` | string | 150 | 大限趋势总述 |
| `risk_boundary` | string | 100 | 风险与边界（命盘局限、无法确定的事项、时辰不确定声明） |

### 3.2 结构与明细字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `patterns` | array | 格局认定，见 3.3。**成立的格局必须给 `break_save`** |
| `pattern_exclusions` | array | **候选表外的排除说明**（第五轮新增）：不在脚本 17 项候选表内的格名（如「三方五吉」「以双帝同宫为条件的格目」）登记在这里，渲染成 §六 独立的「候选表外的排除说明（不参与裁断）」一节，**不写进任何一格的裁断栏** |
| `pattern_summary` | string | 格局总评（层次判断） |
| `palace_details` | array | **十二宫逐宫**，每宫 `{palace, branch, text}`，`text` ≥ 40 字。脚本要求 12 条 |
| `decadal_detail` | array | 大限逐限 `{range, palace, text}`（可选，但强烈建议给未来 2–3 限） |
| `current_year` | string | 流年要点（配合 `chart.horoscope`） |
| `boundary_notes` | array | 边界说明条目（会在「风险与边界」下成列表） |
| `verdict` | string | 一句话总评（可选） |
| `advice` | string | 给当事人的建议（可选） |

### 3.3 `patterns[]` 每项

`prepare_template.py` 会把脚本判定的格局条件填进去，`satisfied` 留空**等你裁断**：

```json
{
  "name": "机月同梁",
  "script_conditions_met": true,
  "script_evidence": "命宫申三方四正内 天机见、太阴见、天同见、天梁见",
  "satisfied": true,
  "evidence": "命宫三方四正齐见四星，为全盘主轴格局",
  "break_save": "层次属中格：天机双重化忌落官禄，稳定性打折；救格在外部助力"
}
```

**规则**
- `script_conditions_met` 只是**古法构成条件是否满足**，**不等于成格**——你要按亮度、辅煞、四化裁断层次。
- `satisfied` 是**三态**，不是布尔：
  | 值 | 渲染出的结论列 | 何时用 |
  |---|---|---|
  | `true` | 成立 | 条件与落点都成立，且不属流派分歧 |
  | `false` | 不成立 | 条件不满足，或条件满足但不主本命格局 |
  | `null` | **存疑／并列** | 成立与否取决于流派口径；并列的理由必须是**真正的**分歧点，不能是已被统一口径解决掉的那一个（见 `interpretation.md` §3.1） |
- `satisfied=true` 时 `break_save` 必填（破格/救格/层次）。
- **每条格局都要有 `nature`（吉／凶／中性）与 `anchor`（该格锚点宫，如 `"辰、戌"`）**
  （末轮新增，缺一则 `--validate` 失败）：
  - `nature` 决定负面栏的**栏名与方向**：吉／中性 → 「破格（减凶条件）」；
    凶 → 「加重条件（煞冲、化忌、失辉）」。
    渲染器按 `nature` 自动生成栏名，写 `break_save` 时不用自己拼栏名；
  - `anchor` 渲染进救格栏名「救格（锚点：X宫）」，也是效力层级尺的原点。
- **`break_save` 有两种形态**（第五轮新增第二种）：
  - 字符串：一整段说明；
  - `[{"label": "破格（减凶条件）", "text": "…"}, {"label": "救格（锚点：辰、戌）", "text": "…"}, {"label": "层次与效力说明", "text": "…"}]`：
    拆成带标签的分段——**破格、救格、层次是不同的事、要分开说清时用这种写法**
    （渲染成同一格里的几个加粗小段）。
- **破格／救格／层次三栏不得串味**（第六轮 B1；审查器 `PATTERN_BREAKSAVE_MISLABELED` 逐栏核对）：
  - **吉格／中性格**的「破格」栏只写**外部削弱条件**（煞冲、空劫、失辉、宫破、逢冲破、
    四化忌——**生年忌与离心自化属四化忌一类，与六煞分列**）；
  - **凶格**的「加重条件」栏写的是让凶性**更重**的条件（煞冲、四化忌、失辉）。
    对凶格写「从外部削弱本格之势」是**方向写反**——凶格遇忌遇煞是加重，使凶性减轻的才是救应；
  - 本格的**形成形态**（亮度只居中上、两邻配置是否对称）写进「**层次与效力说明**」栏；
  - 「**救格折损**」（救应被削）属救格一侧，不得写进破格栏——写了就是概念误用；
  - **救格栏只列独立救应**：本格构成星自身的属性（该星自带的生年禄、该宫宫干自化的禄）
    不算救应，拿它当救应属同义反复（`双禄交流` 的辰侧就没有独立救应）。
- **不成立之格的三栏留空**（`break_save=[]`）：渲染成「—（本格不成立，只留名词与取象）」，
  不得再填破格／救格／层次——判「不成立」只能因为落点或构成条件不满足，
  **不得把「锚点内没有救应」当作不成立的判据**（救应有无只决定凶性折损，不决定格局是否构成）。
- **效力层级照 `interpretation.md` §3.2 的尺写**（第六轮 B2）：
  1 同宫（贴身）＞ 2 两邻（夹）＞ 3 三合会照 ＞ 4 对宫照（含三合宫的对宫）＞ 5 遥会。
  两邻**属贴身层**（写「借宫救应」可以，写「效力次一等」不行）；对宫照不得高于两邻；
  吉星与煞星同宫写「贴身但含煞」；「贴身护格有几颗」只数第 1～2 级。
  写错会被 `EFFICACY_LEVEL_MISSTATED` 拦下。
- **层次标签分两套**：**格层次**（这一格本身，写在破格/救格栏）与
  **命局层次**（全盘，写在 `pattern_summary` 与 `verdict`）——不得混用。
  凶格写「格层次：中下」时要紧跟一句方向说明（夹势不极端、方向是减凶）。
- **不成立即不作格名论断**（第五轮固化的裁断原则）：`satisfied=false` 时不得再用该格名的断语，
  只能改按所涉星曜本身的落宫取象。旧写法「不成立；其意义仅在于外部圈层变动」属**换域解释**，
  与「不成立，故不适用其断语」自相矛盾，审查会按双重标准看待。
- **`null` 时全篇不得在任何位置单方断言**：既不能在结论列写「不成立」，
  也不能在依据/破格救格里写「应标为…成立/不成立」——写了会被
  `PATTERN_VERDICT_CONFLICT` 抓住（表格与正文口径矛盾）。两派落点都要摆出来。
- **条件满足但层次不足的，要写清楚为什么**（例：铃贪格属三合遥会而非同宫，力量次之）。
- 不成立的格局**也要列**，这是防止误套的证据。
- 落点措辞要回盘面核：说「X 与 Y 同宫」就必须真同宫；说「A 夹 B」就必须两颗**正好分居 B 的两邻**
  （同宫不是夹）；说「对宫 X」就必须 X 真在该宫对宫。这三类审查器都会逐句核对。
- **并列枚举要逐星直说**：写「右弼、文曲在戌宫」而不是「右弼、文曲在辰之对宫戌宫」——
  后者里的「在」是共享的，机器会按紧邻读成「文曲在辰」而误报（第五轮实测过的假阳性）。

## 四、语言闸门（可读区禁用词）

脚本会扫描可读区，命中以下任一类即**报错阻断**（`--allow-partial` 可绕过，仅用于草稿）：

| 类别 | 例 |
|---|---|
| 流程门禁类 | 门禁／软门禁、准入条件、检查点、路由表、深断 |
| 审计留痕类 | 本步已加载、证明已真读、落盘、回退方案、判据、子代理 |
| 内部标识类 | `SKILL.md`、`references/`、`ziwei.py`、`generate_report`、schema、JSON 字段名、**脚本／判据**（产出方口径词——读者要的是「排盘结果」「本次判定」） |
| 路径与文件名 | 绝对路径、`*.py`、`*.js`、`*.json`、`*.md` |
| **结构化数据残留** | `{'title': …}`、`"text": …` 这类字典字面量；列表/字典的 repr；Markdown `**强调**` 星号 |
| **祈使式元指令** | 「落点须分开写」「切记…」「不可写成…」「不能写成…」「不得写成…」「不可混称／混用」「务必…」「必须分别写清」——**写给自己看的施工说明** |
| **自校／防守型句式**（第六轮） | 「不宜把必然当发现」「层次要分清」「是两回事」「读法分开处理」「两颗并不共处一宫」「不宜并列／简化／一概而论」——**交稿提醒**，读者要的是结论本身 |
| **自校／免责型说明句**（末轮） | 「不作格名论断」「不替任何一派下结论」「不参与裁断／不进入裁断」「把两条读法的落点都摊开说明」「两说都摊开说明」「仅作名词／只作名词排除」——**作者在交代自己的处理方式**；格局表里要写成「本格不成立，只留名词与取象」这种读者向写法 |

> 最后一类是**独立闸门**（`scan_artifact_leaks`）：它不是「黑话」，而是**内部数据结构被当成正文渲染**。
> 典型来源是列表渲染器漏处理 dict 条目。`strengths` / `weaknesses` 允许两种形态——
> 字符串数组，或 `[{"title": …, "text": …}]`；两种都由脚本渲染成
> `<li><b>标题</b>：正文</li>`，**AI 不得自己把 dict 拼成字符串**塞进任何正文字段。

> **元指令闸门**（`scan_meta_instructions`，第五轮起、第六轮扩类、末轮再扩类）：
> **同类问题第四次出现**（第一次流程词、第二次结构化数据、第三次祈使句+自校句、第四次自校免责句），
> 故继续代码化。判定不是「见到『须』就拦」——
> 汉语里「须」太常用，规则收的是**固定句式的相邻组合**：
> - **祈使式**：须／必须／切记／务必／不可／不得／不能／不要／不许 ＋ 写明／写清／写全／注明／说明／
>   点名／分开写／分开说／分清／并列／声明／混称／混用／标成立／一致／按表／核对／注意…
> - **自校／防守型**：不宜把 A 当 B｜要分清｜是两回事／不是同一回事｜读法／写法分开处理｜
>   并不共处一宫／并不在同一宫｜不宜并列／并论／简化／一概而论
> - **自校／免责型说明句**（末轮）：不（作／做／给／下／替）…（论断／断语／结论／裁断／评价／定论）｜
>   把两条／两说／两种…摊开（并陈／并置）说明｜仅作名词／只作名词排除
>
> 各条之间不许跨句读，于是「力量须靠实际往来维持」「须借对宫…」「太阳不得地」
> 「两处落点分别记明」「不是分居辰戌两宫」「只作结构性提醒」「本格两说并列」
> 一律不命中（每一条都有反例夹具）。
> **成文口径**：给当事人的建议用「**宜／忌**」；「须／必须／切记／务必」只用于写作指令，
> 所以它们出现在可读区即为残留，**命中即阻断**（`--validate` 与 `check_report_language.py` 两处都拦），
> **不做静默剥离**——剥离会改坏句子，而这类话本就不该写进断语。
> 违规句要改写成**读者向的结论本身**（「不宜把必然当发现」→「羊陀夹禄属禄存位置的结构必然，
> 本格鉴别力全在『禄存与忌同宫』」），或移入技术留痕。
