# 强制审查：只审「判断」，不审「事实」

> **铁律：报告生成后、交付前，必须由独立子代理审查一次。** 主流程的作者审查自己的结论 = 无审查。
> 审查用独立上下文（看不到主流程的推理），只拿**盘面数据 + 成品报告**，从零判断。

---

## 一、为什么要这样分工（四轮实测的教训）

本 skill 的示例报告连续四轮被独立审查判 FAIL，把四轮的 30+ 条发现按性质归类后，结论非常清楚：

| 发现的性质 | 占比 | 该谁管 |
|---|---|---|
| 星曜/宫位归属写错、大限宫位算术、计数对不上、术语误用（同宫说成夹）、亮度编造、标记漏项、渲染泄漏、交界分钟数 | **约九成** | **脚本**（可推导，不该由人写） |
| 层次判断、循环论证、破格概念误用、取象过度、建议越界、边界与伦理 | 约一成 | **审查**（无法代码化） |

前四轮之所以每轮都 FAIL，是因为让审查者既当审计员又当判官：**它在替脚本打工**，而真正的判断问题只有寥寥几条。
第三轮审查者自己也说：「格局判法已经干净，剩下的错全在宫位算术。」

**所以本关的铁律是**：可推导事实已经由脚本生成或校验（见第三节），审查者**不要重算它们**，
只审那些**脚本无法判定**的部分。

---

## 二、审查范围：只有这六条

审查者**只**回答下面六个问题，逐条给盘面依据：

| # | 审什么 | 什么算问题 |
|---|---|---|
| 1 | **裁断规则用得对不对** | 「成立/不成立」是否用了该类格局的正确判法：大格看命宫三方四正，**夹宫类看是否正好分居目标宫两邻**（同宫不算夹）。脚本已强制，本项只**抽查**有无绕过。 |
| 2 | **层次判断有没有依据** | 说某格「中格/下格/上格」时，依据是庙旺、煞忌、三方吉曜中的哪些？**有没有循环论证**（用「此格本属盘象描述」解释「为何不成格」这类）。 |
| 3 | **破格/救格是不是真的** | 破格 = 削弱该格的**外部条件**（煞冲、空劫、失辉、宫破、逢冲破）；把**本格的形成形态**（亮度只居中上、两邻配置是否对称）当破格、或把「救格折损」写进破格栏，都属概念误用（`PATTERN_BREAKSAVE_MISLABELED` 会拦）。救格必须真的能救，且**效力层级写对**——按 `interpretation.md` §3.2 那把尺：1 同宫（贴身）＞ 2 两邻（夹，**属贴身层**）＞ 3 三合会照 ＞ 4 对宫照（含三合宫的对宫）＞ 5 遥会。**两邻不得写成「效力次一等」，对宫照不得高于两邻**；吉星与煞星同宫要写「贴身但含煞」（`EFFICACY_LEVEL_MISSTATED` 会拦）。另查**层次标签有没有混用**（格层次 vs 命局层次），以及凶格的「中下」有没有写明方向（减凶而非加重）。 |
| 4 | **取象与断言有没有超出盘面** | 每条断语能否指回具体宫位/星曜？有没有凭常识补充盘面没有的信息（出生地、职业、具体事件）？有没有把徵验讯号当必然事实？ |
| 5 | **边界与伦理** | 死亡时间、绝症诊断、劝阻就医、投资/法律结论；健康与财务是否标「结构性提醒」；徵验率声明与免责是否齐备；免责的**口径来源是否分层**。 |
| 6 | **建议是否空泛或越界** | 建议是否可执行且与该盘结构对应？有没有滑向**操作性投资/医疗建议**（「回避某类标的」「提前留出余量」「预留缓冲」这类措辞属越界，应改为结构性描述）。 |

**范围之外（不要报）**：宫位关系、大限十二宫映射、四化落点、星曜归属、亮度、格局候选清单、各类计数、
六吉六煞的成对／同宫／对拱（照 §二 配对表）、**效力层级的层级词与盘面距离是否相符**（照 §3.2 的尺，
见下）、时辰交界分钟数、渲染与语言问题。这些由脚本保证；
**若你真发现事实层错误，单独标 `[脚本疑似失效]` 并给出复现路径**，
不要混进判断问题里。

## 三、事实层由谁保证（审查者可以信任它，主流程不许绕过）

| 来源 | 保证什么 |

| `ziwei.py chart` 的 `palaces` / `birthMutagen` / `selfMutagen` / `solarTime` | 星曜落宫与亮度、生年四化、离心/向心自化、真太阳时与钟点双轴 |
| `generate_report.py` | **§二 宫位关系表与六吉六煞配对表、§九 大限十二宫落本命表与大限四化落点表、§一 双轴口径** 全部由脚本渲染，AI 只能引用 |
| `audit_report.py`（33 项夹具） | 星曜错位、三方四正误判、夹宫误判（被动式也查）、宫名关系错、大限宫名错、亮度编造、生年四化标记残缺、格局结论冲突、计数不符、结构化数据泄漏、**六吉六煞配对断言错**、**效力层级错**、**破格/救格栏串味** |
| `check_report_language.py --self-test`（42 项） | **元指令**规则本身的夹具与反例：**祈使式**（「须分开写／切记／不可写成…」应检出）＋**自校／防守型**（「不宜把必然当发现／要分清／是两回事／读法分开处理／并不共处一宫／不宜并列」应检出）＋**自校／免责型说明句**（末轮新增：「不作格名论断／不替任何一派下结论／不参与裁断／把两条读法的落点都摊开说明／仅作名词排除」应检出）；反例 20 例不得误报（「须靠／须借／不得地／宜忌／两处落点分别记明／不是分居辰戌两宫／只作结构性提醒／本格两说并列…」） |

> **主流程的硬约束**：正文里凡出现可推导事实，必须与上表字段一致；**能引用字段就不要手写**。

## 四、执行方式

主流程跑完三道脚本闸门后，**用 subagent 起一个独立审查者**，只给它 `chart.json` 与 `report.html`，
不要给推理过程、不要给 `analysis.json`、不要给生成过程与返工记录。把下面这段提示词直接复制给它。

### 审查子代理提示词（可直接复制）

```
你是紫微斗数报告的独立审查者。你没有参与撰写，也不应信任报告中的任何结论。

先明确分工：这张盘的**可推导事实**（宫位关系、大限十二宫映射、四化落点、星曜归属、亮度、
六吉六煞的成对／同宫／对拱、格局候选与构成条件、各类计数、时辰交界分钟数、渲染与语言问题）
已由脚本生成并校验通过。
**你的任务不是重算这些**，而是审那些脚本判不了的部分——判断、裁断、取象、边界、建议。
如果你确实发现事实层错误，单独标 [脚本疑似失效] 并给出复现路径，不要混进判断问题里。

输入：
  · 盘面数据（脚本产出，可信）：<chart.json 路径>
  · 待审报告（不可信，需逐条核对）：<report.html 路径>

只回答这六个问题，逐条给盘面依据：

1. **裁断规则用得对不对**：标「成立」的格局，用的判法是否符合该类格局——
   大格看命宫三方四正；夹宫类（魁钺/昌曲/羊陀/空劫/火铃/羊陀夹禄忌/刑忌夹印）
   看两颗星是否**正好分居目标宫两邻**（同宫不算夹）。有没有绕过脚本强制项？
   另查**口径是否一视同仁**：「夹」的「忌」在本报告里是否只有一个标准
   （生年忌／离心自化忌／向心飞忌一律计入），有没有对 A 格采信、对 B 格又列存疑？
2. **层次判断有没有依据**：某格被定为上/中/下格，依据是庙旺、煞忌、三方吉曜中的哪些？
   有没有**循环论证**（例如用「此格本属盘象描述」来解释「为何不成格」；
   或格名已裁「不成立」却仍引用该格名的断语，只在域上换个说法）？
3. **破格/救格是不是真的**：破格应削弱该格的外部条件（煞冲、空劫、失辉、宫破、逢冲破），
   把**本格的形成形态**（亮度只居中上、两邻配置是否对称）当破格、或把「救格被削弱」写进破格栏，
   都属概念误用；救格必须真有庙旺吉曜或禄权科来扶，且效力层级要写对——
   按 `interpretation.md` §3.2 的尺：1 同宫（贴身）＞ 2 两邻（夹，**属贴身层**）＞
   3 三合会照 ＞ 4 对宫照（含三合宫的对宫）＞ 5 遥会。**两邻属贴身层、不是「次一等」；
   对宫照不得高于两邻**；吉星与煞星同宫写「贴身但含煞」。另查层次标签有没有混用
   （格层次 vs 命局层次），以及凶格写「中下」时有没有写明方向（减凶而非加重）。
4. **取象与断言有没有超出盘面**：每条断语能否指回具体宫位/星曜？有没有凭常识补出盘面没有的
   信息（出生地、职业、具体事件）？有没有把徵验讯号当必然事实？
5. **边界与伦理**：有无死亡时间预测、绝症诊断、劝阻就医、投资/法律结论；
   健康与财务是否标为结构性提醒；徵验率声明与免责是否齐备；
   免责的口径来源是否分层（断语体系／四化表／安星与起限口径）。
6. **建议是否空泛或越界**：建议是否可执行、是否与该盘结构对应；
   有无滑向操作性投资/医疗建议（「回避某类标的」「提前留出余量」「预留缓冲」属越界，应为结构性提醒）。

输出格式（严格）：
  ## 审查结论
  PASS / FAIL（FAIL 即不得交付）

  ## BLOCKER（判断错误或与盘面矛盾，必须改）
  - [位置] 问题 → 依据（引用具体宫位/星曜）→ 建议改法

  ## MAJOR（依据不足或论证不成立）
  - 同上格式

  ## MINOR（措辞、体例）
  - 同上格式

  ## [脚本疑似失效]（可选，仅当你发现事实层错误）
  - 位置 → 盘面字段 → 复现路径

  ## 未覆盖/无法判断

要求：
- 每条问题都要给**依据**，不接受「感觉不对」。
- **不要重算宫位、星曜、四化、计数、分钟数**——那些已由脚本保证。
- 没找到问题就明说 PASS，不要为凑数而报。
```

## 五、处理规则

| 审查结果 | 主流程动作 |
|---|---|
| **PASS** | 可交付。审查全文收进技术留痕 |
| **FAIL + BLOCKER** | **不得交付**。逐条修正 analysis → 重新生成 → 重新审查 |
| **FAIL + 仅 MAJOR/MINOR** | 修正后再交付；确实不认同的，须在报告中写明分歧与理由 |
| **[脚本疑似失效]** | **优先修脚本**（补检测器 + 加夹具 + 反例自测），再重新生成报告 |

**一轮为限**：本审查只跑一轮。若同一类判断问题反复出现，说明它其实**可代码化**，
应变成 `audit_report.py` 的新检测器 + `test_audit.py` 的新夹具，而不是靠下一轮审查再抓一次。

**禁止**：
- 把审查意见「静默忽略」；
- 只改措辞不改结论（如把「成立」改成「基本成立」蒙过去）；
- 审查者与作者是同一个上下文（自己审自己 = 走过场）；
- 让审查者去重算可推导事实（那是浪费一整轮）。
